# Host Import IO

`CoreEval` stays pure: `--eval` still rejects `import ./file.nix` with an
`eval error:`. The new `--eval-imports` path is the first explicit host-side
boundary for local imports.

The host layer resolves relative import paths from the source file's directory,
reads the imported file with `IO.FS.readFile`, then runs the same
parse/validate/desugar/core-validation pipeline used by ordinary input. The
imported file is evaluated in isolation and representable values are reified
back into core syntax before the final pure evaluation pass.

That gives the project a reviewable starting point without pretending imports
are just another pure core expression. Angle paths, home paths, store
realisation, network fetchers, lazy import semantics, and imported functions are
still outside this boundary and remain explicit `eval error:` cases.

The new `e2e/import-manifest.txt` records the contract: one relative import
passes through `--eval-imports`, while unsupported import/path forms are
classified as expected eval failures.
