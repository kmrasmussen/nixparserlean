# Binding trees

Validation now understands the first piece of Nix's attribute tree behavior.

This is valid:

```nix
{
  a.b = 1;
  a.c = 2;
}
```

The two bindings share a prefix, but they land in different leaves of the same
attribute tree.

These are not valid:

```nix
{
  a = 1;
  a.b = 2;
}
```

and:

```nix
{
  a.b = 1;
  a = 2;
}
```

Those are prefix conflicts. One binding says `a` is already a value, while the
other says `a` is an attribute set with a child. The parser can build an AST for
both examples, but validation rejects them as semantic errors.

This is the point where the project starts becoming more than a syntax parser.
The validator is beginning to model the shape that Nix itself imposes on
bindings. Today that model is just duplicate and prefix conflicts. Later it can
grow toward a typed binding tree, clearer source locations, and proofs that
normalization preserves the same attribute paths the evaluator would see.
