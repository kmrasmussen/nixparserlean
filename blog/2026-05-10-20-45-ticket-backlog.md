# A small ticket backlog

The project now has a `.tickets` directory.

This is not meant to replace the working style that has been effective so far:
small reviewable slices, smoke fixtures, blog notes, and commits. The ticket
backlog is for the things that should survive across sessions.

The initial tickets capture the next semantic and proof-oriented frontiers:
recursive attrsets, aliased parameters, `with`, dynamic attributes, import
boundaries, desugaring invariants, termination debt, structured errors, corpus
scale, and string interpolation semantics.

The rule is simple: tickets are the map, commits are the trail. We should keep
the backlog small enough that it remains a useful expression of intent rather
than a second project to maintain.
