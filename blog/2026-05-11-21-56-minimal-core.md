# Minimal Core

The core language has been intentionally surface-like while the evaluator grew.
That was the right tradeoff for coverage, but it makes proof targets larger
than they need to be.

`docs/core.md` now names the intended minimal-core direction:

- primitive and structured values stay as core values;
- lambda/application, conditionals, selection, `hasAttr`, and attr bindings
  remain core computation;
- `with`, selection defaults, the broad operator surface, and `assert` are
  temporary surface-like forms until a smaller rule is chosen;
- imports, path normalization, derivations, store behavior, and search paths
  stay outside pure core evaluation.

The first simplification target is `with`, followed by selection defaults.
Those are concrete enough for the next tickets without forcing a disruptive
core rewrite in this documentation pass.
