# Root Roadmap

The ticket backlog is now empty through `TICKET-0031`, so the project needed a
new planning surface.

The new root `roadmap/` folder separates current state from future tracks:
parser and corpus, core semantics, proofs and totality, host effects, and
project operations. That makes the next session easier to start without
reverse-engineering intent from a long chain of tickets and blog posts.

The important shift is that the roadmap is now driven by the actual state of
the project:

- the external corpus has a small set of named blockers;
- the validators are total fuel-bounded definitions;
- evaluator fuel has an entry-step policy;
- path values are inert;
- host imports are explicit but eager and value-only;
- the remaining proof work is concentrated in desugaring, parser termination,
  and evaluator theorems.

The first recommended work item is the external corpus ratchet for spaced
dynamic selection, followed by a docs freshness pass and then the next
desugaring/evaluator proof slices.
