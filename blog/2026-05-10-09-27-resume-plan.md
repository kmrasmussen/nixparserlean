# Resume plan

The next session should start by finishing the flake-backed e2e loop. The
important direction is clear: Lean owns the Nix parser and model, while Rust
owns corpus orchestration.

The immediate task is to make the flake check boring and reliable:

- confirm `lake build` works under the pinned Lean version
- run the Rust e2e harness inside the flake check
- keep the e2e runner dependency-free until the manifest format proves itself
- make sure the committed smoke corpus has both expected passes and expected
  failures

After that, the next useful parser work is probably lambdas. The current smoke
corpus already includes:

```nix
{ pkgs }:
{
  inherit pkgs;
}
```

and marks it as an expected failure. Supporting that syntax would force the AST
to represent function parameters, which is a meaningful step toward real Nix
code. Once lambdas parse, the expected-failure entry can become an expected pass.

Then the corpus can grow in two stages. First, add more committed fixtures for
specific missing forms: `with`, `if then else`, paths, selections, function
application, and binary operators. Second, add a downloader/cache mode to the
Rust harness so it can pull known `.nix` files from pinned URLs and report parse
coverage without making ordinary development depend on the network.

The rule for scaling should be simple: every time real Nix code fails, either
turn it into a small committed fixture or record it as a manifest case with an
expected outcome. That keeps the project honest without requiring the parser to
be complete all at once.
