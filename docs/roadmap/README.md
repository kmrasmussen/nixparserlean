# Roadmap

Long-horizon plans for the project. Each subfolder owns one theme that spans
many tickets and is too big to live inside a single `.tickets/` entry.

The roadmap is for *direction*, not commitment. Concrete, schedulable work
still belongs in `.tickets/`. A roadmap entry should answer:

- What is the end state?
- What phases get us there, in what order?
- What is the dependency between phases?
- Where is the work currently parked (which tickets, which files)?
